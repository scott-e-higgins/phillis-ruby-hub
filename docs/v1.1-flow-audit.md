# Travel Journal v1.1 flow audit

This pass intentionally keeps the existing visual system, navigation, Supabase schema, authentication, storage, scanners, PWA behavior, and Family Viewer permissions intact.

## Pre-change audit

| # | Flow | Finding | v1.1 response |
|---|---|---|---|
| 1 | Open a current trip | Trip Detail is the right primary context, but frequent actions are scattered. | Add a restrained current-trip action row. |
| 2 | Add a stay from a trip | Requires entering the full Trip editor and scrolling to its stay editor. | Add a direct, trip-linked Stay form. |
| 3 | Add a second stay | Dates must be re-entered even though the trip and prior stay establish sensible defaults. | Start on the prior stay's departure and default through the trip end. |
| 4 | Add an activity from a trip | Trip is already inherited correctly. | Preserve it and make it available from current-trip shortcuts. |
| 5 | Add fuel or DEF from a trip | Trip is already inherited correctly. | Preserve it and keep Everyday Ruby for non-trip purchases. |
| 6 | Add a note from a trip | Trip is already inherited correctly. | Preserve it and make it available from current-trip shortcuts. |
| 7 | Edit the trip itself | Saving returns to the Trips list instead of the Trip Detail. | Return to the same Trip Detail. |
| 8 | Open and close a stay | Returns to the trip, but reconstructs it at the top. | Restore the prior trip section and scroll position. |
| 9 | Open and close an activity | Returns to the trip, but reconstructs it at the top. | Restore the Plans section and scroll position. |
| 10 | Open and close linked note | Returns to the trip, but reconstructs it at the top. | Restore the Notes section and scroll position. |
| 11 | Open and close fuel/DEF | Returns to the trip, but reconstructs it at the top. | Restore the Fuel & DEF section and scroll position. |
| 12 | Scan or attach from a nested record | Existing scanner and document flows are already record-aware. | Preserve them; no scanner rebuild or schema change. |
| 13 | Save over an unstable mobile connection | The browser safety copy works, but a rejected in-memory queue can prevent later saves from starting. | Recover the queue, retry one transient failure, and expose a retry action. |
| 14 | Use Campground Log, Ruby history, or Notes directly | Their parent panels already remain underneath detail dialogs. | Preserve their existing return behavior. |
| 15 | Use Family Viewer | Viewer RPCs and hidden editing surfaces correctly limit access. | Keep viewer rendering read-only and omit all new action controls. |

## Scope guardrails

- No Supabase schema or policy changes.
- No Cellar integration.
- No redesign of the Home screen, bottom navigation, Campground Log, Rig pages, Notes, or established visual identity.
- No removal of browser-local safety copies.

## Verification completed

- Phone-sized current-trip rendering and shortcuts.
- Direct stay defaults, save, explicit trip linking, and return to Trip Detail.
- Activity detail return with the prior Trip Detail scroll position restored.
- Trip edit save returning to Trip Detail.
- Completed-trip rendering without current-trip shortcuts.
- Trip inheritance for Activity, Fuel/DEF, and Note shortcuts.
- Everyday Ruby remains selectable and does not require a trip meter.
- Existing receipt scanner still opens with camera/library, manual-use, and read choices.
- Family Viewer shows stays and plans while hiding all edit/add controls.
- Desktop Trip Detail rendering.
- A simulated Safari-style `TypeError: Load failed` is retried once and completes with a visible saved state.
- JavaScript syntax, JSON manifests, and whitespace checks.
